# 2026-10-19

## 插件系统（DeepWrite）

- 新增 `packages/contracts/src/plugins.ts`：`PluginManifestSchema` / `PluginRecordSchema` / `plugins.*` 命令信封，接入 `system.ts`、`preload-api.ts`、`renderer.ts`。
- 主进程插件宿主：`apps/desktop/src/main/plugins/`
  - `plugin-manifest.ts`（清单与入口校验）、`plugin-registry.ts`（`installed.json` 原子写）、`plugin-installer.ts`（本地目录 / `npm pack` + 自研 ustar 解包 / `git clone`）、`plugin-host.ts`（生命周期、模型注册与同步、内置插件复制）、`plugin-commands.ts`（IPC 分发）。
  - 模型 id 前缀 `plugin-<pluginId>-`；停用/卸载时按前缀移除。
  - 内置插件在构建期由 `apps/desktop/scripts/builtin-plugins.ts` 复制到 `out/main/builtin-plugins`。
- Preload：`src/preload/plugins-api.ts`；Renderer：`PluginSettingsPanel.vue` + `plugin-settings.css`，设置页新增「扩展 → 插件」分类。
- 内置插件 `workbuddy-connect`：复用 WorkBuddy 登录态（AES-256-GCM 信封 + Electron 私有绑定取密钥），读 `~/.workbuddy/local_storage/*.info` 模型目录，随机端口起 OpenAI 兼容反代转发 `copilot.tencent.com/v2/chat/completions`（上游仅流式，插件聚合 SSE）。

### 踩坑

- `pluginHost` 曾在 `index.ts` 里被解构但没赋值给模块级变量，导致 `plugins.*` 全部走 `plugins.unavailable`；改为 `pluginHost = services.pluginHost`，并在 `will-quit` 里 `dispose()`。
- WorkBuddy 模型目录里含图片/视频模型（仅 `tags`，无 `vendor`/`maxInputTokens`），已过滤；对话模型透传 `supportsReasoning` 与 `reasoning.defaultEffort` 作为 DeepWrite 的思考档位。
- `minimax-m2.5` 等少数目录内模型上游返回 400 `service info not found`（账号未开通），无法静态识别，保留并在 README 说明。

### 环境限制（验证时）

- `pnpm` 在本机报 `@pnpm/exe.win32-x64` 缺失，改用 `node_modules/.bin/*` 直接执行。
- 工作区文件是 CRLF 检出，`prettier --check` 会对全仓报错；用 `--end-of-line auto` 校验新增文件。
- `electron-vite build` 清空 `out/renderer` 会触发环境的批量删除保护，需先把该目录移走再构建。
- 全量 `vitest` 有 30 个与本改动无关的历史失败（Windows 无符号链接权限、源码格式断言受 CRLF 影响）。
