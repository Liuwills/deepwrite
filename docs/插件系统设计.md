# 插件系统设计

DeepWrite 的插件用于在不改动主程序的前提下扩展能力。当前只开放「模型供应商」一类能力：
插件自己启动一个 OpenAI 兼容端点（通常是本机反代），再把模型注册进 DeepWrite 的模型选择器。

## 用户界面

设置 → 扩展 → 插件。页面提供：

- 已安装插件列表：名称、版本、来源、运行状态、能力标签、贡献的模型数量、安装位置。
- 每个插件的启用开关（停用后立即撤下它注册的模型）、重新加载、卸载（二次确认）。
- 添加插件：可选择「本地目录 / npm 包名 / GitHub 仓库」三种来源，本地来源支持系统目录选择框。
- 内置插件标记为「内置」，只能停用，不能卸载。

插件以完整权限运行在本机，页面会一直显示这行安全提示，避免用户在不知情时安装陌生代码。

## 目录布局

| 路径 | 作用 |
| --- | --- |
| `<userData>/plugins/<id>/` | 插件安装目录，内置插件首次启动时也会复制到这里 |
| `<userData>/plugins/installed.json` | 安装注册表：来源、版本、启用状态、安装时间 |
| `<userData>/plugin-data/<id>/` | 插件自己的持久化目录，通过 `context.config` 读写 JSON |
| `<app>/out/main/builtin-plugins/<id>/` | 随应用分发的内置插件，构建时由 `scripts/builtin-plugins.ts` 复制 |

内置插件按 `manifest.version` 与注册表比对，版本变化时才重新覆盖复制，因此升级安装包即可更新内置插件。

## 清单文件 `plugin.json`

```json
{
  "id": "my-provider",
  "name": "My Provider",
  "version": "0.1.0",
  "description": "把 My Provider 接入 DeepWrite",
  "author": "you",
  "main": "index.mjs",
  "capabilities": ["model-provider"]
}
```

- `id` 只允许小写字母、数字、`.`、`_`、`-`，最长 64 字符，同时作为安装目录名。
- `main` 必须是插件目录内的相对路径，不能越界，文件不超过 5 MB。
- 清单文件不超过 256 KB。

## 入口模块

入口是 ESM 模块，导出 `activate(context)`，可选导出 `deactivate()`：

```js
export async function activate(context) {
  const port = await startMyProxy(); // 自己实现的 127.0.0.1 服务
  await context.models.registerProvider({
    id: "my-provider",
    name: "My Provider",
    baseUrl: `http://127.0.0.1:${port}/v1`,
    apiKey: "本次会话随机令牌",
    models: [
      {
        id: "my-model",
        label: "My Model",
        contextWindow: 128000,
        maxTokens: 8192,
        reasoning: true,
        defaultThinkingLevel: "medium"
      }
    ]
  });
  context.status.set([{ label: "账号", value: "user@example.com" }]);
}

export async function deactivate() {
  await stopMyProxy();
}
```

`context` 提供：

| 成员 | 说明 |
| --- | --- |
| `plugin` | `id`、`name`、`version`、`directory`、`dataDirectory` |
| `app` | `version`、`platform`、`userDataPath` |
| `logger` | `info` / `warn` / `error`，写入主进程日志 |
| `config` | `read()` / `write()`，读写插件自己的 JSON 配置 |
| `models.registerProvider()` / `unregisterProvider()` | 注册或撤下模型分组 |
| `status.set()` | 写入插件卡片上的运行状态行（账号、有效期、代理地址等） |

模型 id 在 DeepWrite 内会被加上 `plugin-<pluginId>-` 前缀，避免与官方模型冲突；
停用或卸载插件时，这些前缀的模型会被移除。

## 安装来源

| 来源 | 处理方式 |
| --- | --- |
| 本地目录 | 校验 `plugin.json` 后整体复制到插件目录 |
| npm 包名 | `npm pack` 下载 tarball，用内置 ustar + gzip 解析器解包（带路径穿越防护） |
| GitHub 仓库 | `git clone --depth 1` 克隆默认分支 |

安装时先落到临时目录，校验通过后再改名到 `<plugins>/<id>`，失败不会留下半个插件。
单个插件限制 5000 个文件 / 200 MB。

## 安全边界

- `plugins.*` 命令只接受来自主窗口主框架的调用，其它 frame 一律拒绝。
- 插件目录、入口路径、npm 包内的路径都做越界校验。
- 插件是第三方代码，运行在主进程环境里，没有沙箱；这是「只安装可信来源」提示的原因。

## 内置插件：WorkBuddy Connect

`apps/desktop/src/main/plugins/builtin/workbuddy-connect` 复用本机 WorkBuddy 桌面端的登录态：

1. 读取 `CodeBuddyExtension` 的登录凭据（AES-256-GCM 信封，保护密钥由 WorkBuddy 自身的
   Electron 二进制提供）。
2. 读取 WorkBuddy 客户端缓存的模型目录，过滤掉图片/视频类模型，保留对话模型及其上下文
   窗口、推理档位。
3. 在本机随机端口启动 OpenAI 兼容反代，把 `/v1/chat/completions` 转发到
   `copilot.tencent.com/v2/chat/completions`；上游只支持流式，非流式请求由插件聚合 SSE。
4. 把模型注册为 `WorkBuddy` 分组，并在插件卡片上显示账号、登录有效期、模型数量和代理地址。

凭据缺失或过期时插件不会报错退出，而是在卡片上说明原因，重新加载即可再次读取。
